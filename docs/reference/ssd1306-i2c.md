# SSD1306 I2C map

The SSD1306 is an OLED segment/common driver: 128 segment outputs, 64 commons, 128 × 64 bits of
display RAM, an internal charge pump for the panel supply, three RAM addressing modes and hardware
scrolling. It is the controller on the common 0.96" modules and on many 128 × 32 ones.

Every opcode, argument bit and power-on reset value below is the part's, quoted from the Solomon
Systech SSD1306 datasheet (Rev 1.1, April 2008), with the charge pump from the same vendor's
application note.

A 1.3" module is not proof of the controller. Panels sold as SSD1306-compatible are frequently an
SH1106 underneath, which answers most of these opcodes and differs in exactly the places that
matter: it has 132 columns of RAM, no window registers and no scroll commands. A module that shows
its image shifted two columns right, or ignores `0x21`, is an SH1106 wearing an SSD1306 label — the
map for it is [sh1106-i2c.md](./sh1106-i2c.md).

## The bus

The part is an I2C slave at up to 400 kHz. The slave address is 0111100 or 0111101, chosen by SA0 —
the D/C# pad doubles as SA0 in I2C mode — so a module answers at `0x3C` or `0x3D`.

After the address byte comes a control byte: continuation (`Co`, bit 7), data or command (`D/C#`,
bit 6), and six zero bits.

| Co | D/C# | Control byte | What follows |
| --- | --- | --- | --- |
| 0 | 0 | `0x00` | command bytes, to the end of the transfer |
| 0 | 1 | `0x40` | display RAM bytes, to the end of the transfer |
| 1 | 0 | `0x80` | one command byte, then another control byte |
| 1 | 1 | `0xC0` | one RAM byte, then another control byte |

The serial interface is write-only: the datasheet states no data read is provided in serial mode, so
the read display data command is a parallel-bus affair. A status read returns one byte whose bit 6
is `1` for display off and `0` for display on.

## The address space

The RAM is 128 columns by 8 pages. A page is eight rows; one RAM byte is one column of one page, and
within a byte bit 0 is the top row of the page and bit 7 the bottom.

Three addressing modes decide where the pointer goes after each RAM byte, set by `0x20` with
`A[1:0]`:

| `A[1:0]` | Mode | After a byte | At the end of a column | At the end of a page |
| --- | --- | --- | --- | --- |
| `10` | page (reset) | column + 1 | column back to the start column, page unchanged | n/a |
| `00` | horizontal | column + 1 | column back to the start column, page + 1 | both back to their start addresses |
| `01` | vertical | page + 1 | n/a | page back to the start page, column + 1 |

In horizontal and vertical modes the window is set by `0x21` (column start and end) and `0x22` (page
start and end), and a whole frame can be streamed in one transfer. In page mode there are no window
registers: the window is the page from `0xB0`–`0xB7` plus the column from `0x00`–`0x1F`, and both
are page-mode-only commands.

## The commands

### Fundamental

| Opcode | Command | Bytes | Argument | POR |
| --- | --- | --- | --- | --- |
| `0x81` | contrast | 2 | `0x00`–`0xFF`, 256 steps | `0x7F` |
| `0x8D` | charge pump | 2 | `0x10` off, `0x14` on | `0x10` |
| `0xA4`/`0xA5` | entire display off / on | 1 | `0` follows RAM, `1` ignores it | `0xA4` |
| `0xA6`/`0xA7` | normal / inverse | 1 | `0` a set bit lights a pixel | `0xA6` |
| `0xAE`/`0xAF` | display off / on | 1 | `0` off and asleep, `1` on | `0xAE` |
| `0xE3` | no operation | 1 | — | — |

The charge pump is the one command with an order to it: the application note's sequence is `0x8D`,
then `0x14`, then `0xAF`, so the pump is enabled while the display is off and the panel is switched
on afterwards. A module with `VBAT` fed from the header's VCC still needs the pump, and a display
left dark after a correct-looking init usually never had it enabled.

### Scrolling

| Opcode | Command | Bytes | Argument |
| --- | --- | --- | --- |
| `0x26`/`0x27` | horizontal scroll right / left | 7 | dummy `0x00`, start page, interval, end page, dummy `0x00`, dummy `0xFF` |
| `0x29`/`0x2A` | vertical and horizontal scroll right / left | 6 | dummy `0x00`, start page, interval, end page, vertical offset |
| `0xA3` | vertical scroll area | 3 | top fixed rows, scroll rows |
| `0x2E`/`0x2F` | deactivate / activate scroll | 1 | — |

The start and end pages are `B[2:0]` and `D[2:0]`, pages 0–7, and the end page must not be lower
than the start. The interval `C[2:0]` is frames per scroll step: `0` is 5 frames, `1` is 64, `2` is
128, `3` is 256, `4` is 3, `5` is 4, `6` is 25 and `7` is 2. Only the last setup command before
`0x2F` takes effect, and after `0x2E` the RAM has to be written again.

### Addressing

| Opcode | Command | Bytes | Argument | POR |
| --- | --- | --- | --- | --- |
| `0x00`–`0x0F` | lower column start, page mode | 1 | bits 3:0 of the column | `0x00` |
| `0x10`–`0x1F` | higher column start, page mode | 1 | bits 6:4 of the column | `0x10` |
| `0x20` | memory addressing mode | 2 | `0x00` horizontal, `0x01` vertical, `0x02` page | `0x02` |
| `0x21` | column address window | 3 | start and end, 0–127 | `0`…`127` |
| `0x22` | page address window | 3 | start and end, 0–7 | `0`…`7` |
| `0xB0`–`0xB7` | page start, page mode | 1 | page 0–7 | `0xB0` |

`A[1:0] = 11` is the invalid argument for the addressing mode, and `0x21` and `0x22` are ignored
outside the two window modes.

### Panel configuration

| Opcode | Command | Bytes | Argument | POR |
| --- | --- | --- | --- | --- |
| `0x40`–`0x7F` | display start line | 1 | line 0–63 | `0x40` |
| `0xA0`/`0xA1` | segment remap | 1 | `0` column 0 to SEG0, `1` column 127 to SEG0 | `0xA0` |
| `0xA8` | multiplex ratio | 2 | 16–64 rows; `0`–`14` invalid | `0x3F` |
| `0xC0`/`0xC8` | COM scan direction | 1 | `0` COM0 first, `1` COM63 first | `0xC0` |
| `0xDA` | COM pins layout | 2 | `A[4]` `0` sequential, `1` alternative; `A[5]` `0` left/right remap off, `1` on | `0x12` |
| `0xD3` | display offset | 2 | 0–63 rows | `0x00` |

`0xDA` therefore takes `0x02`, `0x12`, `0x22` or `0x32` and, in the form the datasheet writes it,
no other value: `0x12` is alternative pins with remap off, `0x02` sequential with remap off. The
four combinations cover every 128 × 64 and 128 × 32 module: 64-row panels use `0x12`, 32-row `0x02`.

### Timing and driving

| Opcode | Command | Bytes | Argument | POR |
| --- | --- | --- | --- | --- |
| `0xD5` | clock divide and oscillator | 2 | bits 3:0 divide ratio − 1, bits 7:4 oscillator | `0x80` |
| `0xD9` | pre-charge period | 2 | bits 3:0 phase 1 pre-charge, bits 7:4 phase 2 discharge, 1–15 DCLK each, 0 invalid | `0x22` |
| `0xDB` | VCOMH deselect level | 2 | `0x00` 0.65 × VCC, `0x20` 0.77 × VCC, `0x30` 0.83 × VCC | `0x20` |

The ready-made values found in most drivers are `0xD5 0x80` and `0xD9 0xF1` — divide 1 with the
oscillator at its reset setting, and pre-charge 1 DCLK against a discharge of 15. `0xDB` has only the
three levels the datasheet lists, and its argument's bits 3:0 are not part of the level at all;
`0xDB 0x40`, which works on the SH1106 and is copied into SSD1306 drivers from it, asks for a
combination the table does not define.

## The sequences

Power-up: VDD and VBAT up while RES is held low, RES released after the reset period, then the
configuration, then `0xAF`. The reset values in the POR column are what the part holds either way,
so a driver that writes the whole configuration does not depend on the RES pin.

A 128 × 64 module takes this, in one burst up to display on:

| Bytes | Command | What it sets |
| --- | --- | --- |
| `0xAE` | display off | nothing shows while the panel is configured |
| `0xD5 0x80` | clock divide | divide 1, oscillator at its reset trim |
| `0xA8 0x3F` | multiplex ratio | 64 rows |
| `0xD3 0x00` | display offset | COM0 is the first RAM line |
| `0x40` | start line | line 0 at the top |
| `0x8D 0x14` | charge pump | on, while the display is off |
| `0x20 0x02` | addressing mode | page, or `0x00` for horizontal |
| `0xA1` | segment remap | column 127 to SEG0 |
| `0xC8` | COM scan | COM63 first |
| `0xDA 0x12` | COM pins | alternative layout |
| `0x81 0xCF` | contrast | 207 of 256, the usual bright setting |
| `0xD9 0xF1` | pre-charge | pre-charge 1, discharge 15 DCLK |
| `0xDB 0x20` | VCOMH | 0.77 × VCC, the reset level; `0x30` is brighter |
| `0xA4` | follows RAM | the frame, not all-on |
| `0xA6` | normal display | a set bit lights a pixel |
| `0x2E` | scroll off | a scroll set by a previous session stops |
| `0xAF` | display on | the pump is running by now |

A page-mode flush writes, per page, `0xB0 + page`, then the column's low nibble as
`0x00 | (x & 0x0F)` and its high nibble as `0x10 | (x >> 4)`, then a `0x40` control byte and the
page's column bytes. A horizontal-mode driver instead sets `0x21 0 127` and `0x22 0 7` once and
streams all 1024 bytes behind one `0x40`; the pointer walks the pages by itself.

## Against the SH1106

| | SSD1306 | SH1106 |
| --- | --- | --- |
| RAM | 128 × 64 bits | 132 × 64 bits |
| Addressing | page, horizontal, vertical | page only |
| Column and page windows | `0x21` and `0x22`, in horizontal and vertical modes | none: `0x00`–`0x1F` and `0xB0`–`0xB7` |
| Hardware scroll | `0x26`/`0x27`/`0x29`/`0x2A`, `0x2E`/`0x2F`, `0xA3` | none; move the start line |
| Supply for the panel | charge pump, `0x8D` then `0x14` | DC-DC, `0xAD` then `0x8A`/`0x8B`, voltage at `0x30`–`0x33` |
| Oscillator reset | `0x80` | `0x50` |
| VCOM deselect | three levels, `0x00`, `0x20`, `0x30` | 0.430–1.0 × VREF over the byte, `0x35` at reset |
| Visible columns | all 128 | 128 of 132, offset 2 on the common module |
